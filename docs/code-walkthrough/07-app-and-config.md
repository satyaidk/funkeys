The files that turn components into a website (`src/app/`) and the tooling configuration.

## `src/app/layout.tsx`: root layout

```tsx
const instrumentSans = Instrument_Sans({ variable: '--font-instrument', subsets: ['latin'], axes: ['wdth'] });
const dotGothic = DotGothic16({ variable: '--font-dot', subsets: ['latin'], weight: '400' });

export const metadata: Metadata = { title: 'Keyboard Piano', description, openGraph: { … } };
export const viewport: Viewport = { themeColor: '#1a1220' };
```

- **`next/font/google`** downloads fonts at build time and self-hosts them. No runtime request to Google, and no layout shift
- `axes: ['wdth']` loads Instrument Sans's **width axis**, used for the slightly condensed headings (`[font-stretch:90%]`)
- `variable` exposes each font as a CSS variable that `globals.css` maps to Tailwind's `font-sans` and `font-lcd`
- In Next 16, `themeColor` belongs in **`viewport`**, not `metadata`
- `LayoutProps<'/'>` is a global type helper generated by Next.js

## `src/app/page.tsx`

A **Server Component**: the page title, a one-line description, a link to the source, and `<PianoApp />`. Pre-rendered to static HTML at build time.

## `src/app/globals.css`: design tokens

```css
@import "tailwindcss";

:root {
  --stage: #1a1220;   --panel: #26232c;   --led: #ffb547;
  --walnut: #5a3626;  --felt: #7e1a22;    --brass: #c9a15a;   …
}

@theme inline {
  --color-panel: var(--panel);
  --color-led: var(--led);
  --font-lcd: var(--font-dot);
  …
}
```

- **Tokens** are CSS variables; `@theme inline` turns them into Tailwind utilities (`bg-panel`, `text-led`, `font-lcd`)
- One global `:focus-visible` rule gives every control the same amber focus ring
- Keyframes: `key-chase` (power-on sweep), `led-blink` (recording LED), plus `.lcd-grid` (pixel grid) and `.scroll-rail` (hidden scrollbars on sideways rails)
- `@media (prefers-reduced-motion: reduce)` turns off the CSS animations

| --- | --- |
| `"strict": true` | Strictest checking (null safety and more) |

## `package.json` scripts

| Script | Use |
| --- | --- |
| `npm run dev` | Development server with hot reload |
| `npm run build` / `npm start` | Production build / serve it |
| `npm run lint` | ESLint |
| `npm run typecheck` | `next typegen && tsc --noEmit` (see below) |
| `npm test` / `npm run test:watch` | Vitest once / in watch mode |
| `npm run validate` | All of the above, same as CI. **Run before every commit** |

`"engines": { "node": ">=22.12" }` documents the minimum Node version (required by Vite 8).

**Why `next typegen` first?** `layout.tsx` uses `LayoutProps<'/'>`, a *global* type that Next.js generates into `.next/types/` (pulled in by `next-env.d.ts`). `next dev` and `next build` create it, so `tsc` passes on your machine. But `.next/` is gitignored, and CI runs `typecheck` on a fresh checkout *before* `build`, so plain `tsc` fails with `Cannot find name 'LayoutProps'`. `next typegen` generates just those types, in about a second, without a full build: the fix the Next.js docs recommend for CI.

> **Lesson:** "works on my machine" often means "depends on a file my machine generated". Reproduce CI failures in a fresh clone (`git clone` into a temp folder, `npm ci`, run the failing step) before changing anything.

## `.github/workflows/ci.yml`

On every push or pull request to `dev` or `prod`: `npm ci → lint → typecheck → test → build` on a fresh Ubuntu machine with Node 24. `concurrency: cancel-in-progress` stops outdated runs. A red ❌ on a commit means something broke before it reaches a main branch.
