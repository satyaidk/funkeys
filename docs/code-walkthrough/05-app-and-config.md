# Part 5: App shell & configuration

The files that turn the components into a website (`src/app/`) and the config files that control tooling.

## `src/app/layout.tsx`: root layout

### Purpose

Wraps **every page**. It renders `<html>` and `<body>`, loads fonts, sets metadata, and applies `MotionProvider`.

### Code explained

```tsx
const geistSans = Geist({ variable: '--font-geist-sans', subsets: ['latin'] });
```

`next/font/google` downloads the font **at build time** and serves it from your own domain. There's no request to Google at runtime (faster and more private), and no layout shift while the font loads. `variable` exposes it as a CSS variable that `globals.css` maps to Tailwind's `font-sans`.

```tsx
export const metadata: Metadata = {
  title: 'Keyboard Piano',
  description,
  openGraph: { title: 'Keyboard Piano', description, type: 'website' },
};
export const viewport: Viewport = { themeColor: '#0b0b14' };
```

- `metadata` becomes `<title>`, `<meta name="description">` and Open Graph tags, which control the preview card when you share the link on LinkedIn or Slack
- `viewport.themeColor` tints the browser UI on mobile to match the dark design
- In Next 16, `themeColor` belongs in `viewport`, **not** `metadata`

```tsx
export default function RootLayout({ children }: LayoutProps<'/'>) {
```

`LayoutProps<'/'>` is a **global type helper** generated by Next.js. No import is needed, and it knows which props this layout receives.

## `src/app/page.tsx`: the home page

```tsx
export default function Home() {
  return (
    <div className="flex flex-1 flex-col items-center">
      <Header />
      <PianoApp />
    </div>
  );
}
```

A **Server Component** (no `'use client'`). It only arranges two components. The interactive work happens inside `PianoApp`, a Client Component. At build time Next.js pre-renders this page to static HTML (`○ (Static)` in the build output).

## `src/app/globals.css`: global styles

```css
@import "tailwindcss";

:root { --background: #0b0b14; --foreground: #ededed; color-scheme: dark; }

@theme inline {
  --color-background: var(--background);
  --font-sans: var(--font-geist-sans);
}

body {
  background: radial-gradient(…purple glow at top…), radial-gradient(…cyan glow at bottom…), var(--background);
  font-family: var(--font-sans), system-ui, sans-serif;
}
```

- `@import "tailwindcss"` is all Tailwind v4 needs. There's no `tailwind.config.js`; configuration lives in CSS.
- `@theme inline` registers design tokens, so `bg-background` and `font-sans` utilities use these values
- `color-scheme: dark` makes native controls (scrollbars, the range slider) render in dark style
- Two layered radial gradients create the soft purple and cyan stage lighting

## `src/app/icon.svg`: tab icon

Any `icon.svg` in `app/` automatically becomes the favicon. Next.js adds the `<link rel="icon">` tag. It's a gradient tile with a tiny keyboard drawn in SVG shapes; the black keys are centered on the white-key boundaries just like the real layout.

## `tsconfig.json`

| Option | Meaning |
| --- | --- |
| `"strict": true` | Strictest type checking: catches `null`/`undefined` mistakes. Always on in professional codebases |
| `"noEmit": true` | TypeScript only *checks* types; Next.js/Vitest do the actual compiling |
| `"jsx": "react-jsx"` | Modern JSX transform (no `import React` needed) |
| `"paths": { "@/*": ["./src/*"] }` | Lets you write `@/lib/notes` instead of `../../lib/notes` |
| `"lib": ["dom", …]` | Provides browser types like `AudioContext` and `KeyboardEvent` |

## `eslint.config.mjs`

ESLint finds bugs and bad patterns without running the code. This project uses Next.js's recommended rules:

- `core-web-vitals`: React and Next.js best practices, including the **Rules of Hooks** (e.g. no hooks inside `if` statements, complete effect dependency lists)
- `typescript`: TypeScript-specific rules

Run it with `npm run lint`.

## `.github/workflows/ci.yml`

**Continuous Integration.** On every push or pull request to `dev` or `prod`, GitHub spins up a fresh Linux machine and runs:

```
npm ci → lint → typecheck → test → build
```

If any step fails, the commit gets a red ❌ on GitHub. That's how teams make sure broken code never reaches the main branches. `npm ci` (not `npm install`) installs exactly what's in `package-lock.json`, so CI tests the same dependency versions you do.

`concurrency: cancel-in-progress` cancels an older run when you push again quickly, saving CI minutes.
